# AGENTS.md

## Quick Commands

```bash
# Install all system deps + create venv
./setup.sh

# Check environment (no install)
./setup.sh --check

# Run host server (from host/)
cd host && python -m psp_host --output VIRTUAL1 --resolution 1080p --fps 60

# Build Android APK
cd android && ./gradlew assembleDebug --no-daemon

# Run protocol unit tests (only test suite)
python3 -m unittest tests.test_protocol -v

# Interactive management menu (start/stop/virtual display/status)
./start.sh
```

## Architecture

- **Host** (`host/psp_host/`): Python package, entry via `python -m psp_host`. GStreamer pipeline captures screen, encodes H.264/VP9/VP8, streams over TCP.
- **Android** (`android/app/`): Kotlin app, receives TCP stream, decodes via MediaCodec, renders to surface. Touch input sent back as normalized (0..1) coordinates.
- **Protocol** (`docs/PROTOCOL.md`): TCP port 4747. Binary frames (4-byte LE length + flags + payload). JSON handshake negotiates codec/resolution/fps. Flags: bit0=keyframe, bit1=config, bit2=drop, bit7=control.
- **Scripts** (`scripts/`, `host/scripts/`): ADB USB setup, virtual display creation.

## Development Facts

- **Python CI checks**: flake8 (max-line-length=127, max-complexity=15), mypy (`--ignore-missing-imports --follow-imports=skip`), py_compile, unittest
- **Android build**: requires JDK 17, Android SDK. `ANDROID_HOME` and `JAVA_HOME` env vars used by `start.sh`. Default `JAVA_HOME` is `/usr/lib/jvm/zulu-17-amd64` (Zulu JDK 17, not OpenJDK path)
- **host/venv/**: shipped in repo (not gitignored), targets Python 3.14.4, uses `--system-site-packages` (to access system `gi`/PyGObject). Rebuilt by `./setup.sh`. Will fail on systems without Python 3.14
- **host/runtime/**: generated by `host/bundle_runtime.sh`, bundled GStreamer libs. Optional - falls back to system GStreamer. Hardcodes Python 3.14 path
- **`host/run.sh` vs direct `python -m psp_host`**: run.sh sets `LD_LIBRARY_PATH`, `GST_PLUGIN_PATH`, `GI_TYPELIB_PATH` for bundled runtime. Direct invocation skips bundled GStreamer
- **Default port**: 4747 (TCP stream). Discovery uses UDP port 4748 (only one PSP server per LAN segment)
- **Encoder priority**: x264enc > nvh264enc > vaapih264enc > vp9enc > vp8enc (auto-detected). Codec negotiation always returns H.264 regardless of client request
- **Resolutions**: 720p (1280x720), 750p (1280x750), 1080p (1920x1080), 2K (2560x1440)
- **FPS options**: 60, 90, 120, 144. Client sending `fps=0` means "unlimited" (server uses its max)
- **Android minSdk**: 26 (Android 8.0+), ARM-only (arm64-v8a, armeabi-v7a)
- **Wayland**: needs pipewiresrc + portal backend (hyprland/gnome/kde). X11 uses ximagesrc. GNOME Wayland may need EVDI kernel module for virtual display
- **`input` group**: Linux input injection (`evdev` uinput) requires user in `input` group. `setup.sh` adds it but reboot is required. Without it, mouse button/scroll events silently fail
- **`start.sh`**: Hyprland-specific. Uses `hyprctl` for virtual display management. Other compositors get no-ops
- **Keyboard input**: Protocol documents `key` input events but host silently drops them (not implemented)
- **Frame queue**: maxsize=3, non-keyframes dropped when full, keyframes flush queue. Frame drops are by design
- **Android touch**: short tap = left click (btn=1), 500ms long-press = right click (btn=2)
- **`android/local.properties`**: tracked in repo with hardcoded SDK path `/home/silver/Android/Sdk`. Don't rely on it
